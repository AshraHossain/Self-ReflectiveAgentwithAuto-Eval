<objective>
Build `mock_llm.py`: a scripted, framework-free `MockLLM` that emits a fixed sequence of turns — text, tool calls, and usage readings — with no network call and no provider API key, and prove with it that the whole phase's enforcement chain (`decide()` → `SQLiteBudgetLedger` → a scripted client) actually stops a runaway loop before the call that would break the budget, not merely after.

Purpose: ROADMAP's fourth success criterion names this directly — "a mock LLM emits scripted tool calls and non-zero usage, exercised by an automated test with no API key present." It is also where 03-RESEARCH.md's Pitfall 5 lives: if a test's scripted usage happened to equal `estimate_tokens()`'s output, every reconciliation delta would be zero and BUDGET-02 would look tested while proving nothing. This plan is the first point in the phase where `engine.py` (Plan 03-01) and `ledger.py` (Plan 03-02) are driven together by something that behaves like a real LLM client, which is the only way BUDGET-01's "blocked before the call executes" claim can be proven by counting calls rather than by trusting the final state.

Output: `src/eacp/mock_llm.py` (new), `tests/test_mock_llm.py` (new).

Scope boundary: `MockLLM` is core, framework-free utility code. Per-framework wrappers (`FakeMessagesListChatModel` for LangGraph, a `BaseLLM` subclass for CrewAI, `ag2.testing.TestConfig` for ag2) are Phases 5-7's adapters, per CLAUDE.md's Tier 1 testing strategy and 03-PATTERNS.md's classification of this file — this plan builds the thing they will each wrap, not the wrappers.

Source coverage audit for the whole phase: see `03-01-PLAN.md` `<source_audit>`.
</objective>

    iterator — `itertools.cycle(script)` when `loop`, else `iter(script)`. `.complete(self, messages:

    returns the turn; on `StopIteration` (only reachable when not looping) it raises `RuntimeError`
    naming `self.calls`, never lets `StopIteration` propagate to the caller.

      `pytest.raises(PolicyDenied)`. Assert `info.value.decision.rule == "max_cost_per_day"`, and
      — the load-bearing assertion — `mock.calls == EXPECTED_N`, where `EXPECTED_N` is **computed from
      the policy's price and the scripted usage** (e.g. `int(policy.max_cost_per_day //
      cost_of(price, *scripted_tokens))`), never a hardcoded literal. A hardcoded literal could pass
      even if the block fired one call too late; the computed value cannot.
    - `test_runaway_mock_is_stopped_by_max_steps_independent_of_budget` (BUDGET-04) — the same loop
      shape, now with `max_steps` tiny and `max_cost_per_day`/`max_tokens_per_run` enormous. Assert
      `decision.rule == "max_steps"` and `mock.calls == policy.max_steps` exactly.
    - `test_forbidden_tool_call_is_denied_before_the_mock_is_invoked` — a policy whose
      `forbidden_tools` contains a name the test scripts as a `MockToolCall`. Call
      `ledger.admit(run_id, call_key, policy, ToolCall(tool_name=...))` directly — mirroring how an
      adapter would check tool restriction before invoking the real tool — and assert it raises
      `PolicyDenied` with `rule == "forbidden_tools"` while `mock.calls` stays at `0`, proving the
      restriction is enforced by the governance layer itself, not by the mock simply declining to run
      a tool it was never asked to refuse.

      `usage=Usage(None, None, "MISSING")`; `admit()` then `reconcile()` with that turn's usage leaves
