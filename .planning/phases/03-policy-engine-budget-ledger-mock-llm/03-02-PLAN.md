<objective>
Build `ledger.py`: the SQLite-backed, cross-process-safe budget ledger. `SQLiteBudgetLedger.admit()` reads the current budget state, calls `engine.decide()` inside one `BEGIN IMMEDIATE` transaction, and either raises `PolicyDenied` (the call never executes) or reserves the estimate and returns an `Admission`. `reconcile()` then corrects that reservation to the real usage.

Purpose: BUDGET-01 through BUDGET-04 all live here. 03-RESEARCH.md's single most important measured fact governs this plan: copying `store.py`'s legacy implicit-transaction style into a check-then-reserve ledger over-admits 2-4x under real concurrent load — 20-39 calls admitted against a cap of 10, in every probe run. `isolation_level=None` + explicit `BEGIN IMMEDIATE` was exact (10 of 10) in every probe run. This plan also settles the ledger's replay-idempotency design now (G-1), with a caller-supplied `call_key`, rather than deferring a schema change to Phase 5 after Phase 4's audit code already depends on the old shape.

Output: `src/eacp/ledger.py` (new), `tests/test_ledger.py` (new).

    Schema (`_SCHEMA`, one `executescript`): `daily_spend(policy_id TEXT, utc_date TEXT, spent TEXT,
    PRIMARY KEY (policy_id, utc_date))`; `run_usage(run_id TEXT PRIMARY KEY, steps INTEGER, tokens
    INTEGER, missing_usage INTEGER DEFAULT 0)`; `reservations(run_id TEXT, call_key TEXT, policy_id
    TEXT, utc_date TEXT, tokens INTEGER, cost TEXT, reconciled INTEGER DEFAULT 0, PRIMARY KEY (run_id,
    call_key))`. Money is always `str(Decimal)`, dates always `date.isoformat()` — never a `datetime`
    or `date` object handed to the driver (the project's `filterwarnings = ["error::DeprecationWarning"]`
    turns that into a test failure on sight).

    `__init__(self, path, *, clock: Callable[[], datetime] = lambda: datetime.now(UTC))`: mkdir the
    parent, `touch(mode=0o600, exist_ok=True)` + `chmod(0o600)` — copied from `store.py` lines 171-189 —
    then WAL as the first statement, `executescript(_SCHEMA)`, `PRAGMA user_version=1`. The injected
    clock is what lets Task 2's cross-midnight test run without sleeping; `decide()` itself never sees
    it (POLICY-03 stays pure).

    The `_tx()` contextmanager, exactly per §Pattern 2 (lines 311-329): `sqlite3.connect(self._path,
    timeout=30.0, isolation_level=None)`, `row_factory = sqlite3.Row`, `c.execute("BEGIN IMMEDIATE")`
    before `yield`, `c.execute("COMMIT")` after, and on any exception `c.execute("ROLLBACK")` **only if
    `c.in_transaction`** (Pitfall 7 — `BEGIN IMMEDIATE` itself can fail on a busy timeout, and rolling
    back a transaction that was never opened raises a second, misleading error that masks the first).

    `admit(self, run_id: str, call_key: str, policy: Policy, request: LlmCall | ToolCall) -> Admission`:
    inside one `_tx()` — look up an existing `reservations` row for `(run_id, call_key)` first; if found,
    return the `Admission` reconstructed from that row without re-running `decide()` or charging
    anything again (this is this task's half of G-1 — Task 2 adds the test that a row already marked
    `reconciled=1` is handled the same way). Otherwise, read `run_usage` (default `steps_taken=0,
    run_tokens=0` if the run has no row yet) and `daily_spend` for `(policy.policy_id,
    self._clock().date().isoformat())` into a `BudgetState`, call `engine.decide(policy, request,
    state)`. On deny: let the transaction roll back (the `with` block's exception propagates into
    `_tx()`'s `except`) and `raise PolicyDenied(decision)` — the caller never gets a chance to execute
    the call. On allow: `UPSERT` `run_usage` (`steps` +1 always; `tokens` += the estimate only for an
    `LlmCall`), `UPSERT` `daily_spend` (`spent` += the estimate's cost only for an `LlmCall`), `INSERT`
    the `reservations` row with `reconciled=0`, `COMMIT`, and return the `Admission`.

    `reconcile(self, admission: Admission, usage: Usage) -> None`: inside one `_tx()` — `UPDATE
    reservations SET reconciled=1 WHERE run_id=? AND call_key=? AND reconciled=0`; `cur.rowcount == 0`
    means the call_key is unknown or was already reconciled, so `raise KeyError(...)` (copying
    `store.py` line 233's "a silent no-op on an unknown id is worse than a raise" convention). Compute
    the actual tokens/cost: if `usage.usage_source == "MISSING"`, actual equals the estimate (delta is
    zero, never a charge of zero *replacing* the estimate — the estimate stays charged) and increment
    `run_usage.missing_usage`; otherwise actual comes from `usage`'s real counts via `engine.cost_of`.
    Apply `actual - estimate` to `daily_spend` **keyed on `admission.utc_date`**, not
    `self._clock().date()` — a call admitted at 23:59:59 UTC and reconciled after midnight must still
    correct the day it was charged to (Pitfall 3). Apply the token delta to `run_usage.tokens`.

    `spent_today(self, policy_id: str, utc_date: str | None = None) -> Decimal` and `run_usage(self,
    run_id: str) -> RunUsage` (a small frozen dataclass: `steps`, `tokens`, `missing_usage`) are plain
    reads outside any `_tx()` — no lock needed for a read that does not gate a decision.

    `Admission` is a frozen, slotted dataclass: `decision: Decision`, `run_id: str`, `call_key: str`,
    `utc_date: str`, `estimated_tokens: int`, `estimated_cost: Decimal`.

    No agent framework import at any scope; imports are stdlib (`sqlite3`, `contextlib`, `dataclasses`,
    `datetime`, `pathlib`, `collections.abc.Callable`) plus `eacp.engine` and `eacp.errors`.

## Trust Boundaries

|----------|-------------|
| Concurrent processes/threads → the same `ledger.db` | Multiple runs, or a run plus a future diagnostic CLI, reach the same file at once.
