# Phase 3 Review Disposition

| ID | Severity | Summary | Disposition | Notes |
|----|----------|---------|-------------|-------|
| CR-01 | Blocker | `ModelPrice` quantized with default rounding, letting a tiny nonzero price round to exactly `$0`, silently bypassing `max_cost_per_day` for that model at any volume | **fixed** | Reproduced directly (`$0.0000003/Mtok` → stored `0.000000` → `cost_of` returns `0` for 10M tokens). Added a separate `_quantize_price()` using `ROUND_CEILING`, used only by `ModelPrice`'s two fields — `Policy.max_cost_per_day` deliberately keeps its original default-rounding `_quantize_cost`, since rounding a spending *ceiling* up would make it more permissive (wrong direction), while rounding a *price* up only ever makes computed cost more conservative. Verified: the exploit case now yields `0.000001`/non-zero cost; a genuinely free model (`Decimal(0)`) still validates to exactly `0.000000`. Full suite (125 tests), mypy --strict, ruff all green after the fix. |
| WR-01 | Warning | `reconcile()` crashes with an opaque `TypeError` if called with non-`MISSING` usage against a `ToolCall`-derived `Admission` (price columns are `NULL` for tool calls) | **fixed** | Reproduced the crash directly. Rather than the reviewer's inline suggestion applied verbatim, restructured `reconcile()` to SELECT before the claiming UPDATE (previously UPDATE-then-SELECT), so the new misuse check — and the pre-existing unknown/already-reconciled check — both raise *before* any row is mutated. This matters: raising after the UPDATE had already run (as a surface-level patch would) would mark the reservation `reconciled=1` on a rejected call, permanently blocking a corrected retry with `KeyError`. Verified: misuse now raises a clear `ValueError`; a subsequent retry with the correct (`MISSING`) usage still succeeds; double-reconcile is still correctly blocked. Full suite green. |
| WR-02 | Warning | `admit()`'s replay short-circuit doesn't validate a replayed request matches what was originally admitted under the same `call_key` | accepted | Checked against 03-RESEARCH.md's G-1 addendum (the source of this design): G-1 specifies replay-without-recharge but never discusses cross-validating the replayed request against the original — this is a genuine gap in the original design, not a previously-scoped-and-accepted residual, and that distinction is recorded here rather than glossed over. Exploitability requires a caller bug (a `call_key` reused across semantically different requests); the project's test suite uses deterministic, non-colliding keys. Deferred rather than fixed now: a correct fix needs either persisting enough of the original request to compare against, or re-running `decide()` on replay to diff results — real design work, not a one-line guard. **Carried forward:** Phase 4 (the audit log / CLI phase) and Phase 5+ (adapters, which mint `call_key`s per node/call-index) should re-examine this before `call_key` generation becomes adapter-controlled rather than test-controlled. |
| WR-03 | Warning | A replayed `Decision.observed` for `max_cost_per_day` reports this single reservation's cost, not the cumulative daily spend a genuine `decide()` call would report — a correctness gap for a future audit-log reader | accepted | Confirmed against `engine.decide()` (real: `state.spent_today + cost_of(...)`) vs `_replay_decision()` (replay: `Decimal(row["cost"])`, this reservation only) — these are different numbers whenever another call happened the same day. 03-02-SUMMARY.md already documents this as a deliberate G-1 simplification ("only budget/step state... is load-bearing for G-1"); this review doesn't dispute that scoping decision, but confirms the risk the reviewer flagged is real: Phase 3's own SUMMARYs also say Phase 4's audit log can read `Decision` directly, and a reader who does that will get a misleading `observed` value on any replayed admission. **Carried forward:** explicitly flagged for Phase 4's audit-log design — either persist the real `observed`/`limit` at replay time (same precedented move as the price columns), or mark replayed decisions as synthetic (distinct `rule` value or an `is_replay` flag) before Phase 4 builds against `Decision` as if every instance came from a live `decide()` call. |
| IN-01 | Info | Dead logic in a test assertion (`decision.limit is not None or decision.limit == 0` — the `or` clause can never change the outcome) | **fixed** | One-line simplification to `assert decision.limit is not None`. Zero behavior change, zero risk. |

**Outcome:** 1 blocker fixed (closes a real, reproduced silent budget-bypass), 1 of 3 warnings fixed (the crash-to-clean-error fix required restructuring `reconcile()`'s ordering, not just adding a check), 2 warnings accepted as genuine new gaps carried forward to Phases 4/5 with a concrete reason rather than dismissed, 1 info fixed. All fixes independently verified against the installed package (not just re-stated from the review) and the full test suite (125 tests) plus mypy --strict and ruff stay green throughout.
